# GM addon

## When to use

A GM wants common commands without typing full chat commands, while staying inside the server's RBAC
and audit rules.
## Install

Copy the addon folder into the 3.3.5a client:

```text
World of Warcraft/Interface/AddOns/GMHelper/
```

It must contain:

```text
GMHelper.toc
GMHelper.lua
GMHelperInstances.lua
```

Enable **GM Helper** on the character-select AddOns screen, then log in.

## Open

```text
/gmhelper
/gmh
```

## What it does

The frame has three tabs.

### Commands

- `.server info`
- `.instance listbinds`
- `.gm on` / `.gm off` behind one **GM mode** toggle
- `.gm visible on` and `.gm visible off` as explicit **Visible to players** / **Hidden from players** buttons
- `.unstuck`
- `.pinfo <target>`, `.npc info`
- `.lookup item|creature|quest|spell|player account <text>`
- `.teleport <location>`

### Instances

Every dungeon and raid, in two scrollable columns: Dungeons on the left, Raids on the right, each
grouped by expansion separators. Click an instance to teleport to its entrance (`.go xyz` with the
entrance coordinates from `areatrigger_teleport`). The tooltip shows the map id and level range.
The list lives in `GMHelperInstances.lua`, generated by `tools/dev/gen-instance-manifest.py` from
`LFGDungeons.dbc` and `areatrigger_teleport`; rerun the generator after client-data or database
changes.

### Self

One-click sends for the solo-verification set. Every command acts on the GM's own character, even
with another player targeted: named commands pass the GM's own name, and the cheat handlers are
session-player code in the core.

- `.cheat god`, `.cheat power`, `.cheat cooldown`, `.cheat casttime`, `.cheat explore 1/0`
- `.combatstop`
- `.character level <own name> 80`, `.revive <own name>`
- `.modify speed 2` and back to 1 (sets walk, run, swim, and flight speed; this core has no `run`
  subcommand)
- `.modify money 1000g` — gold for the GM's own character
- `.additem <own name> 51809 4` — four Portable Hole 24-slot normal bags
- `.instance unbind all <own name>` and `.instance listbinds`

The cheat buttons carry no state label because the addon cannot read the server state; click once
to flip a toggle, again to flip it back.

Self-only is enforced server-side for the commands without a name argument: `.modify money`,
`.modify speed` (the bare/all handler), and `.cheat explore` operate on the session player and
never on the selected target. Fork decision recorded here; the other `speed` subcommands (walk,
swim, fly) keep their admin-target behavior.

Every button sends the normal chat command. The addon does not call the database and does not add a
permission path.

The GM mode button tracks the request, not server confirmation. It starts at off after `/reload`; a
denied command, a chat-typed change, or a combat-blocked click can desync it, so click once to
resync. Combat clicks do not flip the label. Visibility stays as two explicit buttons because hiding
is security-sensitive and the client cannot reliably read the server state.

## Test

1. Log in with a role account on the test realm.
2. Run `/gmhelper`; the three tabs render, **Commands** is active.
3. Click `.server info`; output appears in chat.
4. Click **GM mode** twice; chat shows `.gm on` then `.gm off`, and the label follows.
5. Enter combat and click **GM mode**; the label must stay unchanged.
6. Click **Visible to players**, then **Hidden from players**; run `.gm visible` to confirm each state.
7. Look up an item; it works for `support` and above.
8. Type into each lookup and teleport field; the full input box and text must be visible.
9. Open **Instances**: Classic/Burning Crusade/Lich King headers appear with Dungeons and Raids
   subgroups; the list scrolls; every row reads from `GMHelperInstancesData`.
10. Click a Classic instance row; chat shows the `.go xyz ...` command and the character teleports
    to the entrance. Confirm the map id in the tooltip matches the row.
11. Open **Self**: click **God mode**; chat shows the command and god mode flips. Click again to
    flip back. **Level 80 (self)** and **Clear my lockouts** behave as their typed equivalents.
12. Try a command the role does not have, such as `.additem` from `support`; the server denies it.
13. Confirm attempts in `acore_test_auth.gm_audit_log` on the test realm (or `acore_auth` locally),
    or via the GM API.

Checked on the local realm on 2026-11-13: menu, GM mode toggle, visibility buttons, lookups,
teleport, and input rendering. Instances, Self, and the two-column teleport list (0.3.0) are new and need the same local
client pass. Test realm client login remains unverified; use the local realm for client checks.

## Test offline (no client)

The client ships its FrameXML inside `Data/enUS/*.MPQ`. The addon harness extracts the real
template/font list and loads the addon against a mock of the WoW UI API, so template, font, slash
registration, and layout bugs are caught without launching the game:

```bash
python3 -m pip install --user mpyq                     # once
python3 tools/dev/addon-harness/extract-client-frames.py   # refresh client-frames.txt after a client update
lua tools/dev/addon-harness/run.lua tools/gm-addon/GMHelper.toc
```

The runner validates every `CreateFrame` template and font object name, registers the slash
command, clicks tabs and instance rows, clicks every Self-tab button and requires the exact
self-only command forms, and flags text wider than its button. It exits non-zero on any failure.
It runs the same Lua the client runs but cannot render pixels; visual
checks still need a screenshot (the client saves PNGs to `~/Games/wotlk-test/Screenshots/`, which
the agent can read directly).

## Client FrameXML quirks (wotlk-test client)

Hard rules learned from real failures; the offline harness enforces the template ones:

- `GameTabButtonTemplate` does not exist in this client's FrameXML. Build tab strips from
  `UIPanelButtonTemplate` and swap `SetNormalFontObject` for the active state.
- A template-less `Button` has no FontString, so its `SetText` renders nothing. For text-only
  clickable rows (accordion headers), use a `Frame` with `EnableMouse(true)`, an `OnMouseUp`
  script, and a child FontString created with `CreateFontString`.
- `PanelTemplates_SetTab` resolves tabs as `_G[<frame name>.."Tab"..i]` and touches
  template-internal textures. Either name tabs exactly `<frame name>Tab<i>` or manage tab state
  manually; managing it manually is what GM Helper does.
- Template buttons render ~34 px tall regardless of `SetHeight`. Set row pitch to at least 26 and
  size buttons from their label (`fontString:GetStringWidth() + padding`); fixed widths clip the
  label on long text.
- Addons load only at login. After changing files, `/reload` in world (or relog), then confirm the
  version banner in chat (`GM Helper <version> loaded`); a missing banner means the file did not
  load.
- An addon Lua error at load kills the whole file, so the slash command vanishes with no visible
  trace in the addon list. Run `/console scriptErrors 1`, then `/reload`, to surface the error text.

## Security

- The server remains the permission gate.
- The addon stores no credentials.
- No destructive buttons. Bans, grants, RBAC, and shutdown stay on the CLI/API until the future
  website provides confirmation and audit flows.
- Command output can contain player data; do not paste it into public channels.

## Troubleshooting

- Addon not listed: check the folder name is `GMHelper`, not `gm-addon`.
- `/gmhelper` unknown: enable the addon and `/reload`.
- A button does nothing: the command was denied, the target is missing, or the player is in combat.
- Wrong role: check the role grant with `.rbac account list` or the RBAC runbook.
